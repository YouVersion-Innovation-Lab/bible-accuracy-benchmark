# Bible Accuracy Benchmark — v0.3

**Status:** current · **Generation:** 2026-07 · **Supersedes:** [v0.2](v0.2.md)

v0.3 keeps v0.1's structure — the same three deterministic tracks, the same
Overall Score formula, the same 11 languages — and fixes the largest source of
error in the Scripture in Answers track: **it was scoring faithful quotations as
misquotes.**

> **Overall Score** = 100 × (0.50 × Direct Quotation + 0.25 × Scripture in Answers + 0.25 × Hallucination Resistance),
> each track averaged across the languages it covers.

For the tracks and scoring, see [v0.1](v0.1.md) and [v0.2](v0.2.md); only the
differences are described below.

## The problem this release fixes

Asked what the Bible says about colonialism, GPT-5.6 Terra quoted four verses —
each in double quotation marks, each with its reference immediately after, each
labelled with the translation it came from (NRSVUE). Exactly what the benchmark's
system prompt asks for.

It scored **0.23 out of 1.0**, because:

1. **The translation wasn't in the accepted list.** Scripture in Answers compared
   quotations against seven hand-picked English translations. NRSVUE wasn't among
   them, so four faithful quotations were measured against text the model never
   claimed to be quoting. Against NRSVUE the same four quotes score **1.000,
   0.918, 1.000, 1.000**.
2. **Identity was inferred from the nearby reference.** The scorer decided *which
   verse* a quotation was by reading the reference printed beside it. When a
   response contains several quotations, that window can pick up the *previous*
   one's citation — here Isaiah 10:1 and Galatians 3:28 were recorded as citing
   Exodus 22:21 and Luke 4:18, so even a perfect match was unreachable.

The item's true accuracy was **0.98**. The same mechanism was depressing the
track for every model, and doing it invisibly.

## Changes from v0.2

1. **Quotations are identified by content, across every translation.** A quoted
   span is matched against **all** translations the API offers for its language —
   229 across the 11 languages, from 6 (Korean) to 87 (English) — with no
   reference consulted. Detection is two deterministic stages: an inverted
   n-gram index over each translation's whole text proposes candidate verses
   (word 4-grams for spaced scripts, character 8-grams for CJK/Thai/Khmer/Lao/
   Myanmar, where word tokens don't exist), then character-level similarity
   confirms. Thresholds were tuned for full recall while proposing ~0.3% of a
   translation's verses.

   Consequences: **quoting any real translation faithfully counts as faithful**;
   a mis-associated reference can no longer cause a false misquote; and the
   result records **which translation the text actually matched**.

2. **Attribution is judged separately from accuracy.** Whether the model's own
   citation agrees with the verse it actually quoted is now a distinct
   observation rather than the basis of the verdict. In the Hallucination
   Resistance track that distinction still decides the outcome (a real verse
   pinned to the phantom reference fails); in Scripture in Answers, accuracy is
   about the words.

3. **No prompt names a translation any more.** v0.2's L1 prompt asked for a
   specific translation ("…from the NIV translation"); v0.3 asks only for the
   relevant verses. Both levels now leave the choice to the model, and **which
   translation it prefers is recorded as a finding** (`version_preference`, now
   counted at both levels) instead of being prescribed. This is a more honest
   measurement — real users don't specify a translation either — and it makes the
   two levels differ in exactly one way: whether quoting is requested.

4. **Partial quotations score as partial quotations — fidelity × coverage.** A
   quotation is judged on two separable things, which earlier versions conflated
   in opposite directions:

   - **fidelity** — are the quoted words right? Measured by aligning the model's
     own quoted span inside the verse, so a faithful fragment is faithful (1.0),
     not a partly-wrong whole verse.
   - **coverage** — how much of the verse was actually delivered, capped at 1.0.

   The score is their product, and the grade (accurate / minor / misquote) comes
   from fidelity alone. So a verbatim full verse scores 1.0; a verbatim half
   verse is *accurate* but scores ~0.5; a garbled quotation scores 0 however much
   of the verse it covers. v0.1–v0.2 credited any fragment at 1.0; the first v0.3
   cut swung the other way and scored verbatim fragments 0, because detection
   measures how much of the *verse* is present — which for a faithful fragment
   sits below the misquote threshold.

5. **One quotation, one verdict.** Several verses can legitimately match the same
   words — Luke 4:18 quotes Isaiah 61:1, and translations of a psalm echo each
   other — so only the best-matching verse per stretch of text is scored.
   Otherwise the runners-up were counted as separate misquotes and dragged down
   the average for a quotation the model got right.

6. **Anything presented as a quotation always gets a verdict.** Content-first
   detection only yields matches for text that *is* scripture, so invented text
   produces no detection at all. A marked quotation that matches no verse in any
   translation is therefore recorded explicitly as fabricated (score 0) — without
   that, inventing a verse would vanish from the topical average and read as
   "quoted nothing", which is a *pass* on the hallucination track.

7. **Attribution is adjacency-gated.** Only a reference sitting next to a
   quotation counts as a claim about it: a generous window after it (the form the
   system prompt asks for) and a tight one before. A reference elsewhere in the
   answer leaves the quotation unattributed rather than borrowing someone else's
   citation. This matters most for the ideal hallucination-track answer — deny the
   fake reference, then offer a real verse — which the first v0.3 cut scored 0,
   because the reference being *denied* was read as the substitute's attribution.

5. **Full-Bible cache.** `prefetch` now enumerates and downloads every
   translation of every benchmark language (~272,000 chapters, ~1.2 GB) and
   records the language→translations manifest in the cache, so scoring can search
   the full set while runs stay offline.

## Why it matters

- **The headline problem was measurement, not model behaviour.** A benchmark that
  marks correct answers wrong is worse than no benchmark, because the number
  looks credible. This release removes the two mechanisms that did it.
- **Translation-neutral by construction.** Nothing hinges on guessing which
  translation a model will use, so a model is never penalised for preferring one
  we didn't anticipate.
- **A new, genuinely interesting result:** with no translation prescribed
  anywhere, the benchmark now reports which translation each model reaches for,
  per language, when left to choose.

## Unchanged from v0.2

Tracks, weights and the Overall Score formula; the 11 languages; the
character-level accuracy metric and severity grades for Direct Quotation; A × E
topical scoring (quoting nothing still scores zero); the graded hallucination
ladder; fail-fast on any exhausted-retry model call; "an empty response scores
zero"; the deterministic-only principle (no model ever influences a score); and
the scope disclaimer — accuracy of quoted scripture only, never theology.

## Re-running

v0.3 changes the prompts, so v0.2 results are not comparable and every model must
be re-run. Prefetch first (it is idempotent and resumable):

```bash
bible-bench prefetch
bible-bench run --base-url … --model … --label "…" --api-key-env …
bible-bench publish --model …
```
