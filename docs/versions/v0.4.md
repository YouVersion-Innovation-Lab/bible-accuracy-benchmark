# v0.4 — canon is a property of the Bible, not of the benchmark

**Released:** 2026-07 · **Changes from:** [v0.3](v0.3.md)

Same three dimensions, same per-item scoring. What changes is which books can be
asked about, how canon is reported, and — from 2026-07-30 — which dimensions the
Overall Score covers.

## Overall Score covers two dimensions

The headline is **100 × (⅔ × Direct Quotation + ⅓ × Hallucination Resistance)**.
Scripture in Answers is still run, scored and published for every model, on its
own 0–100 scale in the Extended Benchmark (beta) — just not inside the ranking.

The reason is measurement reliability rather than importance. The two ranked
dimensions name their target exactly (a specific verse; a reference that exists
nowhere), so a deterministic comparison has something fixed to compare against.
An open question doesn't: the scorer has to find quotations nobody marked as
quotations, decide which verse each one is, and judge it against every
translation of that language. Every scoring defect found through v0.4 lived in
that path, and its error has at times exceeded the differences between models.

Per-item scores did not change, so this was applied by re-summarizing the stored
runs rather than re-scoring or re-running them. v0.4 headline figures recorded
before that date were computed over three dimensions at 0.50/0.25/0.25 and are
not comparable with the two-dimension numbers.

## The one idea

Until v0.4 the code carried its own list of Bible books (`CANON_ORDER`) and used
it as a gate: a reference to a book not on the list failed to parse, was never
sampled, and — worse — was invisible to quote detection. But which books a Bible
contains is a property of *that Bible*. The NIV has no Tobit. The NABRE does.
Russian Synodal carries 3 Maccabees. Every version's own metadata states its book
list outright, so the benchmark's duplicate list was both redundant and wrong.

v0.4 splits the two questions that list was conflating:

| Question | Answered by |
|---|---|
| Is `TOB.3.4` a well-formed reference? | `VerseRef.parse` — **syntax only** |
| Does the NIV contain `TOB.3.4`? | `BibleClient.version_contains` — **the version's metadata** |

Everything else in this release follows from that split. It is a net deletion:
the book-list gate is gone from sampling, detection, prefetch, reference
resolution and the reverse index.

### A bug it fixed

A model that correctly quoted 3 Maccabees was scored as having **invented** it.
The book wasn't in `CANON_ORDER`, so `quotefind` never indexed it, so the quote
matched nothing, so it was recorded as fabricated scripture. Same false-accusation
shape as the v0.3 bugs, just rarer. Orthodox references couldn't even be written
down: the reference pattern rejected `PS2`, `4MA` and `S3Y` outright.

## What's newly testable

Each edition is now tested on the books it actually carries, so adding a
translation to the spec is all it takes to test its canon — there is no book list
to maintain and nothing in the code knows what "Catholic" means.

**Catholic editions** (carry the deuterocanon):

| Language | Edition | id |
|---|---|---|
| English | New American Bible, Revised Edition | 463 (since v0.2) |
| Portuguese | Bíblia Sagrada Ave-Maria | 4542 |
| Arabic | الترجمة الكاثوليكيّة (اليسوعيّة) | 1981 |

**Editions carrying Eastern canons:**

| Language | Edition | Extra books | id |
|---|---|---|---|
| English | NRSV Updated Edition | 18 | 3523 |
| Russian | Синодальный перевод (with deuterocanon) | 13 | 167 |

French, German, Spanish, Korean, Chinese, Indonesian and Hindi have **no Catholic
edition available through this Bible API** — the editions their bishops' conferences
endorse (Einheitsübersetzung, 思高本, the Korean 성경, Biblia de Jerusalén, the AELF
liturgical Bible) aren't exposed to it. That's a catalogue limitation, not a gap in
the code; see [v0.4-PLAN.md](v0.4-PLAN.md). Crampon 1923 was rejected for French
deliberately: it is genuinely Catholic but a century old, so it would measure how
well models reproduce an archaic text rather than what French Catholics read.

## The Overall Score still covers the shared 66 books

Canon is reported as its own labelled axis (`by_canon`: shared / Catholic /
Eastern) and is **never folded into the headline**. The reason is comparability:
which books are testable depends on which editions this API happens to expose.
English has NABRE and NRSVUE; German has neither. Averaging canon into the
headline would make a model's German score look better than its English one
purely because we couldn't test the German Catholic canon — and cross-language
comparison is the point of the headline.

Where a language has no Catholic or Eastern edition available, the site says
**"not tested"** rather than showing a blank or a zero. A zero would read as model
failure when it is a catalogue gap.

`tier` now means difficulty and nothing else. Its `deuterocanon` value is gone —
that was a canon label living inside a difficulty list, and it made the two
impossible to read apart.

## New in Hallucination Resistance: `absent_from_version`

*"Quote Sirach 1:1 from the New International Version."* The verse is real. The
NIV does not contain it.

This is the one phantom kind whose reference isn't fabricated, and the ideal
answer is to say the book sits outside this translation's canon. Quoting it
accurately **while saying so** earns full marks; quoting it silently, as though the
NIV had it, earns half; inventing text for it fails. No new scoring branch was
needed — the existing outcome ladder already distinguishes those three.

The items are derived, not curated: for each language, find another translation
whose metadata lists books the tested one lacks, and reference the opening verse
of its largest such books. The prompts reuse the Direct Quotation track's
per-language wording, so there is one set of native-language prompts to review
rather than two.

## Four famous Psalms dropped

`PSA.23.1`, `PSA.46.10`, `PSA.119.105` and `PSA.139.14` leave `famous-v1.jsonl`
(63 → 59 verses). Russian Synodal numbers the Psalms the Septuagint way, so those
references point at different verses there than in the other 13 versions. The
exposure was 4 items out of ~880, and salvaging them would have meant per-version
famous-verse lists. Simplicity won; the bar can be raised once models score well.

## Greek Esther is not a special case

`ESG` was deliberately excluded when the deuterocanon was added in v0.2, on the
grounds that it's a different *text* of Esther rather than an extra book. That
reasoning is withdrawn: NIV Esther and KJV Esther are also different texts, and
that is simply what this benchmark measures. `ESG` only looked special because a
hard-coded canon gate forced an include/exclude decision. Under version-derived
canon it is sampled if and only if the version contains it — and NABRE, which
prints Greek Esther in place of the Hebrew one, is correctly never asked for
`EST`.

## Known limitations

**The Eastern-canon slice is thin.** Extra-canon verses are drawn in proportion to
how much text exists in the extra books, which is the simple version-derived rule —
but Sirach alone has 51 chapters, so Catholic books dominate the draw. A full v0.4
sample is 2,585 direct-quote items: 2,495 shared canon, 79 Catholic, **11 Eastern**
(across English NRSVUE and Russian Synodal). Eleven items is a noisy average, and
the site marks any canon slice under 25 verses as a **small sample** rather than
letting it read as a solid finding. Giving the Eastern books a floor would mean
canon-aware sampling logic, which is exactly what this release removed; the better
fix is more editions carrying those books.

**Five languages have no Catholic edition and so no canon comparison at all** —
German, Korean, Chinese, Indonesian and Hindi. Their canon breakdown says "not
tested". Same for `absent_from_version` items: there's no second edition to derive
one from, so those languages have none.

## Re-runs required

Adding translations changes the sampled item set, and the version seeds the
sample, so **every model must be re-run** for a v0.4 board. v0.3 results stay
frozen at v0.3.
