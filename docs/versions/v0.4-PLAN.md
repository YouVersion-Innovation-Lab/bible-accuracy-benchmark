# v0.4 plan — a Catholic Bible in every language

**Status:** draft for review · **Depends on:** v0.3 board complete

## Goal

Every benchmark language should test the translation Catholics in that language
actually use, not just a Protestant one. v0.2 added NABRE for English; this
extends that to all 11 languages, and with it the deuterocanonical books those
canons contain.

Why it matters beyond coverage: v0.3's first run showed direct-quote accuracy of
**24.7** on deuterocanonical verses against **94.8** on famous ones. If that
holds, "models are far weaker on the Catholic canon" is a real, publishable
finding — and right now it rests on one translation in one language.

## How candidates are identified

Not by name. **A Catholic Bible is one that carries the deuterocanon**, which the
version metadata states outright, so candidates are found deterministically:
enumerate every translation of a language and keep those carrying ≥5 of
`TOB, JDT, WIS, SIR, BAR, 1MA, 2MA` (see `usfm.DEUTEROCANON`). Name matching
would miss editions that don't say "Catholic" and falsely flag ones that do.

Picking *which* candidate is the commonly-used one is a judgement call — that
part needs research and sign-off (see Open questions).

## Step 0 result: our enumeration is NOT the problem

Checked. The API accepts **only ISO-639-3 tags** — `de`, `zh`, `zh-Hans`, `ko`,
`pt-BR` and every other form return an error, and the ISO-639-3 counts match what
we already had. There are no hidden translations. German really does expose 14
versions, all Protestant (Luther, Elberfelder, Schlachter, Hoffnung für alle,
Neue Genfer…); Korean 6; Chinese 8 (Union Version, CCB, CNV, RCUV…); Indonesian
10; Hindi 9.

So the five gaps are a **real limitation of the API surface**, not a bug in our
code — and v0.3's quote detection is searching the full available set after all.

## What the Church actually endorses

Canon law (1983) entrusts approval of scripture translations to the Apostolic See
and to each episcopal conference, so "endorsed" is a real, per-territory status —
not a matter of popularity. The authoritative edition per language, and whether
this API carries it:

| Language | Church-endorsed edition | Status of endorsement | In the API? |
|---|---|---|---|
| eng | **NABRE** | USCCB-approved | ✅ **463, in spec** |
| por | **Bíblia Ave-Maria** | first Catholic Brazilian translation, the most widely used | ✅ **4542** |
| arb | **Catholic Arabic Version** | self-identified Catholic edition (provenance to confirm) | ✅ **1981** |
| fra | **AELF *Bible liturgique*** | approved by all French-speaking bishops, *recognitio* of the Holy See — the first complete official French Catholic Bible | ❌ (API has Crampon 1923, id 504) |
| spa | **Biblia de Jerusalén** | approved for liturgical use | ❌ |
| deu | **Einheitsübersetzung** | adopted by the German Bishops' Conference (1978; revised 2016) — the liturgical text | ❌ |
| zho | **思高本 / Studium Biblicum** | the authoritative Chinese Catholic scripture (Bl. Gabriele Allegra, 1968) | ❌ |
| kor | **성경** | standard for the Church in Korea since 2005 (CBCK), replacing the Common Translation | ❌ |
| ind | Alkitab Deuterokanonika (LAI Katolik) | research incomplete | ❌ |
| hin | research incomplete | | ❌ |
| rus | Synodal is what Russian Catholics generally use | Orthodox-approved, carries the deuterocanon | ✅ 167/400 (already tested) |

## This changes what v0.4 mainly is

Only **three** languages currently have a genuinely Catholic edition available
(English, Portuguese, Arabic). For five more, the edition the Church actually
endorses **is not in this API at all** — so no amount of spec editing reaches it.

The primary action is therefore a **request to YouVersion**, not a code change:
ask whether Einheitsübersetzung, 思高本, the Korean 성경, Biblia de Jerusalén and
the AELF liturgical Bible can be exposed to this API. Several are almost certainly
in the YouVersion catalogue already; the constraint may be licensing or this
endpoint's scope rather than absence.

Sequenced accordingly:

- **v0.4a (no dependencies)** — add Portuguese Ave-Maria (4542) and Arabic CAV
  (1981) alongside English NABRE, extend deuterocanon sampling to those languages,
  and add the canon breakdown to the site. Takes Catholic-canon coverage from 1
  language to 3.
- **v0.4b (needs YouVersion)** — add the remaining endorsed editions once exposed.
- **French: wait for AELF.** Crampon 1923 is rejected — it is genuinely Catholic
  but a century old, so it would measure how well models reproduce an archaic text
  rather than what French Catholics actually read. French gets no Catholic edition
  until the AELF liturgical Bible is available.

## Orthodox canons — available now, and currently invisible to us

The Orthodox canon extends beyond the Catholic seven: 1–2 Esdras, 3–4 Maccabees,
Prayer of Manasseh, Psalm 151, Odes, Letter of Jeremiah, Greek Esther and Greek
Daniel (with Susanna, Bel and the Dragon, the Prayer of Azariah). A scan of all
229 cached translations for those USFM codes:

| Translation | Orthodox books carried |
|---|---|
| **rus Synod (167)** | 6 — `1ES 2ES 3MA DAG ESG LJE` |
| **eng NRSVUE (3523)** | **11** — `1ES 2ES 3MA 4MA BEL ESG LJE MAN PS2 S3Y SUS` |
| eng CEB (37) | 11 |
| eng RSV-C (2017) | 10 |
| eng engWEBUS (206) / WEBBE (1204) | 7–8, incl. `3MA 4MA PS2` |
| por NTLH CE (4539) | 6 |
| spa TLAI (178) | 5 |

Frequency across all translations: Greek Esther 31, Letter of Jeremiah 18, Greek
Daniel 15, Prayer of Azariah 14, Bel 13, Susanna 13, 1 Esdras 12, 2 Esdras 11,
Prayer of Manasseh 11, 3 Maccabees 6, Psalm 151 6, 4 Maccabees 5, Odes 1.

So Orthodox coverage is achievable immediately: **Russian Synodal (167)** is the
natural Orthodox pick — Russian Orthodoxy is the largest Orthodox body and that
edition is already prefetched — with **English NRSVUE (3523)** carrying the fullest
canon of any translation available.

### ⚠️ A live problem this exposed

`usfm.CANON_ORDER` contains the 66 Protestant books plus the Catholic seven, and
nothing else. Two consequences **today**, not in v0.4:

1. `VerseRef.parse` raises on any Orthodox reference, so 3 Maccabees, Psalm 151,
   Prayer of Manasseh and the rest can never be sampled.
2. `quotefind.load_verses` skips books not in `CANON_ORDER`, so those books are
   **absent from the quote-detection index**. A model that correctly quotes
   3 Maccabees is therefore scored as having *invented* it — the same
   false-accusation shape as the bugs fixed in v0.3, just rarer.

The fix is small (extend the book tables) and is worth doing regardless of whether
Orthodox editions are added to the spec, because it removes a way to be wrong.

### Testing the extra text specifically

The existing deuterocanon sampling pass is already version-specific — it draws
those books only from translations whose metadata carries them — so it generalises
directly. Proposed shape:

- `usfm.py`: add the Orthodox codes to `BOOK_NAME_TO_USFM` / `CANON_ORDER`, and
  introduce `ORTHODOX_CANON` alongside `DEUTEROCANON`.
- `spec-v1.json`: a `orthodox_canon` block mirroring `deuterocanon`, so those books
  are sampled with their own item counts.
- Report a **canon dimension**: score by canon (Protestant 66 / Catholic
  deuterocanon / Orthodox extras) per language. Given deuterocanon already scores
  24.7 against 94.8 for famous verses, the Orthodox books — rarer still in training
  data — are likely lower again, and that gradient is the interesting result.
- Revisit **Greek Esther (`ESG`)**, deliberately excluded when the deuterocanon was
  added. It appears in 31 translations including NABRE, and is a different *text* of
  Esther rather than an extra book, so it needs a deliberate decision rather than
  silent omission.

## Open questions for you

1. **Who signs off on the picks?** "Most commonly used by Catholics" is a
   pastoral/editorial judgement, not a technical one. I can propose from research
   plus the deuterocanon scan, but YouVersion likely has people who know each
   market. This joins the existing per-language version-ID review already on the
   release checklist.

2. **If a language has no Catholic edition in the API, what then?** Options:
   skip that language for the canon comparison; use an interconfessional edition
   carrying the deuterocanon and label it as such; or ask YouVersion whether the
   translation exists but isn't exposed via this API.

3. **Should Orthodox canons be treated separately?** Russian Synodal carries the
   deuterocanon on an Orthodox basis, and Orthodox canons include books beyond the
   Catholic seven (3 Maccabees, 1 Esdras, Psalm 151…). Today `DEUTEROCANON` is the
   Catholic seven only. Extending to Orthodox books would be a further step, and
   arguably deserves its own slice rather than being folded in silently.

4. **Weighting.** More translations per language means more direct-quote items,
   shifting the balance of the language's score toward whichever canon has more
   editions. Worth deciding whether per-language scores should weight translations
   equally or weight canons equally.

## Decisions taken (2026-07-25)

**Q1 — headline over the shared canon.** The Overall Score covers the 66 books
every version has; Catholic and Orthodox canons are reported as their own labelled
slices. Reason: canon availability differs per language (English has NABRE, German
has no Catholic edition in the API at all), so folding canon into the headline
would make a model's German score look better than its English one purely because
we couldn't test the German Catholic canon. Cross-language comparison is a headline
output and must not depend on catalogue accidents.

**Q2 — no special case for Greek Esther.** Withdrawn. NIV Esther and KJV Esther are
also different texts and that is simply the benchmark. `ESG` only looked special
because the hard-coded canon gate forced an include/exclude decision; under
version-derived canon (Option B) it is sampled iff the version contains it.

**Q3 — drop the 4 famous Psalms.** `PSA.23.1`, `PSA.46.10`, `PSA.119.105`,
`PSA.139.14` leave `famous-v1.jsonl`, taking it from 63 to 59 verses. Only Russian
Synodal (400) is Septuagint-numbered (Psalm 9 has 39 verses vs ~20 in the other 13
versions), so the exposure was 4 items out of ~880 — but simplicity wins over
salvaging them, and the bar can be raised later once models score well.

⚠️ **Not applied yet, deliberately.** `famous-v1.jsonl` is read at sampling time and
the v0.3 runs were in flight when this was decided. Editing it mid-generation would
mean a later v0.3 run drew a different item set from the earlier ones, breaking the
guarantee that every model at a version faces identical items — the property that
makes the leaderboard a fair head-to-head. Apply with the v0.4 bump.

Also queued for v0.4 from the architecture review:
- `parse` = syntax / `version_contains` = semantics (the keystone change)
- delete `DEUTEROCANON`, the `spec["deuterocanon"]` block, and the `CANON_ORDER` gate
- extend the book-*name* table to Orthodox books (names ≠ validity)
- `by_canon` reporting derived from each version's book set, replacing
  `tier="deuterocanon"`
- new phantom kind `absent_from_version` ("quote Tobit 3:4 from the NIV")
- guard the phantom attribution check against versification differences (accept a
  citation matching the verse in any version's numbering)

## Website work for canon reporting

Q1's decision — headline over the shared 66 books, canons as labelled slices — is
mostly a *presentation* commitment, so the site work is as much of v0.4 as the
engine work. Today canon is visible only as `tier="deuterocanon"` inside a
*difficulty* list, which is the category error the review identified.

**Data contract.** `summarize_simple` gains `by_canon` (`{protestant, catholic,
orthodox}` → score) and `canon_counts` (items per canon), derived from each
version's book set — not from a hard-coded list. `tier` loses its `deuterocanon`
value and returns to meaning difficulty only. Each `VersionScore` gains
`canon_profile` so the site can group versions by canon. `headline_score` is
computed over Protestant-66 items only; `by_canon` is reported alongside, never
folded in.

**1. Model detail — canon breakdown.** A fourth block in `DimensionBreakdown` for
the Direct Quotation dimension: score and item count per canon, with the shared
canon marked as the one feeding the headline. This is where the finding lives — on
current data it reads roughly *Protestant ~80 / Catholic ~25 / Orthodox (TBD)*, and
that gradient is the story.

**2. Leaderboard — a canon column group, off by default.** The main matrix stays
language × Overall (comparable everywhere). Add an optional "by canon" view rather
than new default columns: most readers want one number per language, and canon
coverage is uneven per language, so showing it by default would invite exactly the
misreading Q1 avoids.

**3. Header filter — add canon.** Alongside language and version. Selecting
*Catholic* narrows every number on the page to deuterocanonical items, reusing the
existing filter plumbing. Needs the same treatment as the version filter: dimensions
that don't vary by canon must say so rather than silently ignoring it.

**4. Evaluations pages — label each test case.** Show the canon a verse belongs to
next to its reference, and allow filtering to one canon. For the new
`absent_from_version` phantom kind, the "show your work" panel should state plainly
*"the NIV does not include Tobit"* — that is the whole point of the item and it must
not read as an ordinary phantom reference.

**5. Methodology + version doc.** Explain why the headline covers the shared canon
and canons are reported separately, in the same terms as Q1: so cross-language
comparison doesn't depend on which editions the API exposes. State that a model is
never scored on a theological position — only on whether text it was asked for is
reproduced accurately.

**6. Empty-state honesty.** Where a language has no Catholic or Orthodox edition
available (German, Korean, Chinese, Indonesian, Hindi today), the canon view must
say *"not tested — no such edition available"* rather than showing a blank or a
zero. A zero would read as model failure when it is a catalogue gap.
